一、核心认知：为什么 AI 测试不一样

传统软件是确定性的：输入 A 必然输出 B，失败会抛异常、断言会明确失败。而 LLM 是概率性、非确定性的：同一个输入可能产生不同输出，正确性是一个分布，而不是二值。LLM 不会“大声”失败——它会生成一段语法完美、语气自信、但事实完全错误的回答，而传统断言什么都抓不到。

这决定了 AI 测试的核心命题：用「指标 + 阈值 + 评测集」替代「精确断言」，用「评测（evaluation，eval）体系」替代「单点测试用例」。这也是面试官最想听到的第一句话。

三、面试考点（考点 → 考察点 → 答题要点）

概念考点 1：LLM 测试与传统软件测试的本质区别是什么？

考察点：是否理解“非确定性”这一核心难点，能否跳出“精确断言”的思维定式。

  • 答题要点：LLM 输出是概率分布而非二值；正确性是统计性的，需通过指标（指标分数）而非布尔断言来度量。
  • 失败模式是“安静失败”（confident wrong answer），传统断言无法捕获。
  • 因此要建立「评测指标 + 阈值门禁 + 黄金评测集」三件套，回归测试用评测集而非单条用例。

概念考点 2：什么是幻觉检测？有哪些方法？

考察点：对 Hallucination 的定义与方法体系的掌握程度。

  • 答题要点：幻觉 = 模型生成与事实/上下文不符但表述自信的内容；分为内在幻觉（与给定上下文矛盾）与外在幻觉（与外部事实矛盾）。
  • 方法：基于上下文一致性（Faithfulness 指标）、基于外部知识检索验证、LLM-as-a-Judge 打分、人工抽检。
  • 工具落地：DeepEval 的 HallucinationMetric、RAGAS 的 Faithfulness。

概念考点 3：离线评测 vs 在线评测，怎么选？

考察点：是否理解两条评测链路的分工与适用场景。

  • 答题要点：离线评测（offline）= 用标注好的黄金数据集在发布前批量打分，可控、可复现，适合回归与版本对比。
  • 在线评测（online）= 对线上真实流量采样，用无参考评测器（reference-free）打分，捕获离线没预料到的输入。
  • 两者是互补的分层关系：离线做门禁（发布前），在线做持续监控（上线后），互相反哺——线上异常沉淀为离线回归用例。

概念考点 4：LLM-as-a-Judge 有哪些偏差？如何缓解？

考察点：这是高分题，考察对评测方法局限性的深度认知。

  • 答题要点（三类经典偏差）：位置偏差（position bias，偏好排在前面的回答）、冗长偏差（verbosity bias，偏好更长回答）、自偏好（self-preference，模型给自己的输出打更高分）。
  • 缓解：固定评分 rubric（明确评分标准）、随机交换答案顺序、使用更强的 judge 模型并固定版本、引入少量人工校准（gold label 对照）。

概念考点 5：BLEU / ROUGE / BERTScore 为什么不适合开放域评测？

考察点：是否理解“词面重叠”指标的局限，以及何时该用语义类指标。

  • 答题要点：三者都是基于参考（ground truth）的词面/嵌入相似度，奖励“字面重合”而非“事实正确”。
  • BLEU 适合翻译、ROUGE 适合摘要——这些任务有标准参考答案；开放问答、RAG 生成没有唯一标准答案，用它们会漏判“语义对但措辞不同”的好答案。
  • 替代方案：LLM-as-a-Judge（G-Eval）或任务专用指标（如 RAGAS 的 Faithfulness / Answer Correctness）。

RAG考点 6：RAG 评测的核心指标有哪些？各自测什么？

考察点：对 RAGAS 标准指标体系的掌握，能否说清每个指标“回答什么问题”。

  • 答题要点（RAGAS 五指标）：Faithfulness（忠实度，回答是否被检索到的上下文支撑）、Answer Relevancy（回答相关性，是否切题）、Context Precision（上下文精确率，检索到的内容是否相关）、Context Recall（上下文召回率，必要信息是否都被检索到）、Answer Correctness（回答正确性，与 ground truth 对比）。
  • 一句话分层：Precision/Recall 测检索器，Faithfulness/Relevancy 测生成器，Correctness 测端到端。

RAG考点 7：RAG 出问题，怎么定位是检索器还是生成器的锅？

考察点：工程化的排查思维，能否将系统拆成组件分别测（component-wise evaluation）。

  • 答题要点：关键在“分离测试”——把 RAG 拆成检索段和生成段分别评估。
  • 检索器用 Context Precision / Context Recall 衡量；生成器用 Faithfulness / Answer Relevancy 衡量。
  • 若检索召回高但回答仍错 → 生成器/提示词问题；若忠实度低但检索相关 → 生成没用好上下文。这样能精准定位是索引、嵌入、还是 prompt 的问题。

Agent考点 8：Agent 评测和纯 LLM 评测有什么不同？

考察点：是否理解 Agent 的“多步、带工具、有环境反馈”特性带来的评测差异。

  • 答题要点：Agent 是“多轮交互 + 工具调用 + 环境状态变化”，比单轮文本生成更复杂。
  • 评测目标分四维：行为（黑盒任务完成）、能力（工具调用/规划/记忆）、可靠性（重复执行一致性）、安全对齐。
  • 核心指标：任务完成率/success rate、pass@k（k 次尝试至少一次成功，测能力上限）、pass^k（k 次全成功，测稳定性）。

Agent考点 9：怎么测 Agent 的可靠性与工具调用正确性？

考察点：对 Agent 可观测性（observability）与轨迹追踪的实践理解。

  • 答题要点：可靠性用 pass^k（多次重复全成功）衡量一致性；工具调用正确性通过轨迹追踪检查每一步 action 是否正确选择了工具、参数是否合理。
  • 落地：用 LangSmith / Langfuse / Phoenix 等做轨迹追踪（tracing），把 Agent 的每一步（思考、工具调用、观察）记录为可审计的 span。
  • 同时关注 prompt injection（注入攻击）：Agent 可能被用户输入诱导执行危险工具调用，需做安全对抗测试。

Agent考点 10：多 Agent 协作场景怎么测？

考察点：高阶题，考察对 2025-2026 多 Agent 评测前沿的了解。

  • 答题要点：多 Agent 评测不仅看最终任务完成，还看协作过程——通信质量、规划一致性、任务分配合理性。
  • 指标：任务完成里程碑 + 通信得分 + 规划得分，加权成 Coordination Score（协调分）。
  • 参考基准：MultiAgentBench / MARBLE（合作与竞争场景，支持 star/chain/graph 多种协作结构）。

工程考点 11：给你一个 LLM 产品，怎么从 0 搭一套 eval 体系？

考察点：这是最常见的“开放设计题”，考察体系化落地的完整思路。

  • 答题要点（六步法）：① 明确评测目标与关键维度（正确性/忠实度/安全性/成本延迟）；② 构建黄金评测集（含边界与对抗用例）；③ 选指标与评测框架（DeepEval / RAGAS / Promptfoo）；④ 设定阈值门禁，接入 CI/CD；⑤ 做 LLM-as-a-Judge 并做人工校准；⑥ 上线后持续在线采样 + 漂移监控。
  • 强调“分层”：开发期用评测框架做门禁，生产期用可观测平台（LangSmith/Phoenix）做持续监控，两套并行。

工程考点 12：怎么把 eval 接入 CI/CD，又不被 LLM 的非确定性搞崩？

考察点：工程稳健性，考察对“flaky 评测”的控制经验。

  • 答题要点：不要用精确阈值，用容差带（tolerance band）——如 faithfulness ≥ 0.7 且不较上次下降超 0.05。
  • 固定 judge 模型版本（pin version）、固定黄金评测集、用稳定采样，避免噪声波动导致构建随机失败。
  • 评测作为独立 pipeline 阶段，跑在每次 push 上，超阈值才 fail。

工程考点 13：评测框架怎么选？（DeepEval / RAGAS / Promptfoo / LangSmith）

考察点：对主流框架定位的判断力。

  • 答题要点：DeepEval = 开发期评测库（pytest 风格，指标最全）；RAGAS = RAG 专用指标（学术标准词汇）；Promptfoo = CI 门禁与红队/多模型对比（YAML 声明式）；LangSmith = 生产期追踪 + 评测平台（LangChain 生态）。
  • 成熟团队通常两套并行：开发期用 DeepEval/Promptfoo 做门禁，生产期用 LangSmith/Phoenix 做监控。

框架定位开源/协议适用场景
DeepEval开发期评测库（“LLM 的 pytest”）开源（Apache 2.0）CI 门禁、指标最全（14+ 内置，含 G-Eval、DAG 自定义）

PromptfooCI-first、提示词回归 + 红队开源（MIT）YAML 声明式、多模型矩阵对比、500+ 对抗攻击向量

Braintrust商业评测平台商业实验追踪、评分历史、人工标注工作流
Arize Phoenix可观测 + 评测（OpenTelemetry）开源核心嵌入漂移检测、生产监控、可自托管
lm-eval-harness基座模型基准测评开源（MIT）选基座模型（MMLU 等 200+ 学术基准），非应用评测
关键提醒：区分「评测应用」和「基准测评」——HELM / lm-eval-harness / MMLU-Pro / GPQA 是选基座模型的，不是评价你应用好坏的。混淆两者是最常见的认知错误，也是面试官爱挖的坑。

五、阶段学习资源建议

阶段一（LLM 基础）

  • 深入理解 LLM 生成机制：Transformer 注意力、采样策略（temperature/top-p）与输出不确定性。
  • 动手：用 DeepEval 写第一个评测用例，跑 HallucinationMetric / AnswerRelevancyMetric。

阶段二（RAG）

  • 掌握 RAGAS 五指标定义与计算原理，能说出每个指标“回答什么问题”。
  • 动手：搭一个最小 RAG 应用，分别测检索器和生成器，做一次“分离测试”定位。

阶段三（Agent）

  • 研究 Agent 评测四维目标与 pass@k / pass^k 指标，理解轨迹追踪。
  • 动手：用 browser-use + Playwright 做一次 Agent 浏览器任务评测，接入 LangSmith 看轨迹。
