# 大语言模型核心原理

面向测试开发工程师的原理层笔记，采用「生活化比喻 → 数学与原理」的由浅入深路径。全篇回答四个问题：**与传统 ML 有何不同 → 底层架构是什么 → 如何理解与生成 → 如何被训练出来**。

> 与 [[wiki/AI相关学习资料/大模型必学基础知识|大模型必学基础知识]] 的分工：本页聚焦**底层原理深度**（RNN 局限、词向量、QKV 推导、训练三阶段细节）；必学基础知识聚焦**应用技术分层**（Token 预算、采样参数、提示词/上下文工程、Agent/Skill/MCP、评测体系）。

## 一、LLM 与传统机器学习的差异

| 对比维度 | 传统机器学习 | 大语言模型 |
|---|---|---|
| 核心任务 | 分类、回归、预测（有明确标签） | 语言生成（预测下一个 Token） |
| 数据依赖 | 大量人工标注数据 | 海量原始文本（自监督） |
| 通用性 | 一个模型解决单一任务 | 一个模型泛化到翻译/问答/写作/编码 |
| 规模 | 几千 → 几亿参数 | 几十亿 → 数万亿参数 |
| 输出 | 类别标签 / 数值 | 自然语言序列 |

> **一句话**：传统 ML 是「喂答案」，LLM 是「喂语料、自学语言」。核心规律是 **Next Token Prediction（预测下一个词）**。

**⚠️ 测试启示**：LLM 本质是**概率模型**，不知道「真理」只知道「语言统计规律」——这正是幻觉的根源，也是 AI 测试不能沿用「返回 == 期望值」断言、必须转向**评测（eval）**的根本原因。

## 二、底层架构：Transformer

### 2.1 为什么需要 Transformer（RNN 的两大局限）

| 局限 | 本质问题 |
|---|---|
| 串行计算，速度慢 | 训练无法并行，大数据集效率极低 |
| 长距离依赖丢失 | 梯度消失/爆炸，模型「记不住」较远信息 |

> Transformer 的诞生动机：既要**并行计算**，又要**记住长距离依赖** → **注意力机制（Attention）** 登场。

### 2.2 Transformer 的核心思路

出自论文《Attention Is All You Need》（Vaswani et al., 2017）：**不再是「接力读」，而是「一眼看全 + 重点关注」**。

![Transformer 编码器-解码器架构（论文原图 Figure 1）](../../_attachments/images/AI相关学习资料/transformer_architecture_paper.png)

**三大关键特性**：并行化（所有词同时处理）、长距离依赖（任意两词直接建联）、可扩展（堆叠层数 + 增参数 → 能力变强，即「大」模型的由来）。

**架构组成**：
- **Encoder（编码器）**——「阅读理解」：输入 → 词嵌入 → 多头自注意力 → 前馈网络 → 输出语义向量
- **Decoder（解码器）**——「复述写作」：掩码自注意力 → 交叉注意力（与编码器交互）→ 前馈网络 → 输出下一个词

| 核心组件 | 作用 | 生活化比喻 |
|---|---|---|
| 词嵌入（Embedding） | 把词变成数字向量 | 给每个词发一张「身份证号」 |
| 位置编码（Positional Encoding） | 告诉模型词的前后顺序 | 给每个词标上「第几个出场」 |
| 多头自注意力 | 计算词与词之间的关联强度 | 找出「谁和谁关系密切」 |
| 前馈网络 | 对每个词做特征变换 | 对每个理解进行「消化加工」 |
| 残差连接 + 层归一化 | 让深层网络稳定训练 | 给高层建筑加「电梯和地基」 |

### 2.3 注意力机制：把公式读成「查资料」

> **Attention(Q, K, V) = softmax( Q·Kᵀ / √d ) · V**

| 符号 | 含义 | 比喻 |
|---|---|---|
| **Q**（Query） | 我在找什么？ | 「猫摸到了什么？」 |
| **K**（Key） | 每个词的「标签」 | 每个候选资料的标签 |
| **V**（Value） | 每个词真正携带的语义内容 | 候选资料的实际内容 |
| Q·K → softmax | 算匹配度并归一化成注意力权重 | 每个词跟「猫」有多相关 |
| ×V | 按权重加权汇总 | 「头」权重最高 → 取到答案 |

**论文三大贡献**：提出注意力机制取代 RNN 循环结构；多头注意力（从多视角理解句子）；完全并行化。

## 三、运行机制：从 Token 到生成

### 3.1 Token——最小处理单元

| 语言 | 拆分方式 | 例子 |
|---|---|---|
| 英文 | 子词（subword） | "unhappy" → "un" + "happy" |
| 中文 | 字 / 词 / 常见子词 | "我爱你" → "我" + "爱" + "你" |

**重要性**：上下文窗口以 Token 计量（128K、1M）；计费按 Token 计；模型一次只能处理有限 Token。**测试提示**：长文本测试与上下文长度评估需关注 Token 用量与截断问题。

### 3.2 词向量与词嵌入

**词嵌入（Word Embedding）**：把词映射为**低维稠密向量**，让计算机能「算」词间语义关系。语义相近的词在向量空间中聚成簇。

![词向量语义聚类示意图](../../_attachments/images/AI相关学习资料/Simple_conceptual_illustration_2026-09-09T08-58-52.png)

| 模型 | 年代 | 特点 |
|---|---|---|
| Word2Vec | 2013 | 经典，能捕捉类比关系（国王−男人+女人≈女王） |
| GloVe | 2014 | 基于全局共现统计，效果稳定 |
| BERT / GPT 嵌入层 | 2018+ | **上下文相关**，现代 LLM 主流方案 |

> **核心进阶点**：早期是**静态词向量**（「苹果」在哪都一个向量），现代 LLM 是**动态（上下文相关）词向量**——「吃苹果」和「苹果公司」编码结果不同。这是 LLM 理解力强大的关键之一。

### 3.3 自注意力与多头注意力

**自注意力（Self-Attention）**：Q/K/V 都来自**同一个句子**，每个词都去「看」其他所有词并判断关联强度。

![自注意力机制示意图](../../_attachments/images/AI相关学习资料/Simple_flat_illustration_of_th_2026-09-09T08-58-50.png)

**多头注意力（Multi-Head Attention）**：让模型从多个不同角度同时理解——有的头关注语法结构，有的关注指代关系（「它」指什么），有的关注主题关联；多个头结果拼接得到更丰富的语义表示。

### 3.4 生成过程与解码策略

![大语言模型预测机制示意图](../../_attachments/images/AI相关学习资料/Simple_flat_educational_illust_2026-09-09T08-58-51.png)

生成本质是**逐步预测下一个 Token**：输入编码 → 结合注意力理解语境 → 输出概率分布 → 按策略选词 → 拼接回输入继续预测。

- **自回归生成（Autoregressive）**：逐字生成，每次依赖此前全部内容
- **解码策略**：贪心（选概率最大）/ 采样（按概率随机）/ Top-k / Top-p
- **温度（temperature）**：低温更确定保守，高温更发散有创意

> **测试实践提示**：生成类用例断言不能只看「内容是否等于期望」，而要看**语义是否合理**与是否满足**约束**（JSON 格式、关键词、长度区间）。建议引入**语义相似度 + LLM-as-a-Judge + 规则校验**多层断言策略。

## 四、训练三阶段：预训练 / SFT / RLHF

![预训练-SFT-RLHF 三阶段流程图](../../_attachments/images/AI相关学习资料/Three_stage_flow_illustration__2026-09-09T08-58-50.png)

### 4.1 学习范式对照

| 学习范式 | 数据情况 | 大模型中的应用 |
|---|---|---|
| 监督学习 | 输入 + 正确答案 | **SFT** 阶段 |
| 无监督/自监督 | 只有原始数据 | **预训练**阶段 |
| 强化学习 | 奖惩反馈 | **RLHF** 阶段 |

### 4.2 三阶段详解

| 阶段 | 数据 | 目标 | 产出 | 比喻 |
|---|---|---|---|---|
| ① 预训练 | 海量互联网文本（约几万亿 Token） | 学会语言本身与世界知识 | 基座模型（Base Model） | 「识字、博览群书」 |
| ② SFT | 人工标注的「指令-回答」对 | 学会听指令、按格式回答 | 指令跟随模型（Chat Model） | 「学会答题规范」 |
| ③ RLHF | 人类偏好排序 | 更安全、有用、对齐价值观 | 对齐后的对齐模型 | 「学会讨人喜欢、守规矩」 |

**RLHF 三步骤**：① 收集人类反馈，训练**奖励模型（RM）**；② 用奖励模型做强化学习（**PPO**），并加 KL 惩罚项防止跑偏；③ 迭代优化。

> ChatGPT 比 GPT-3 好用很多，**关键一步就是 RLHF**。

**⚠️ 测试视角**：理解三阶段有助于分层设计 AI 产品测试用例——**预训练**关注知识与能力、**SFT** 关注指令遵循与格式、**RLHF** 关注安全性与偏好对齐。

## 五、高频面试考点（对标 17-22K AI 测试岗）

1. **Transformer 为什么替代 RNN**：并行 + 长距离依赖 + 可扩展
2. **自注意力 vs 多头注意力**的区别
3. **Token 与词嵌入的关系**，以及静态 vs 上下文相关向量
4. **预训练 / SFT / RLHF 三阶段**各自的目标、数据、范式
5. 结合 AI 测试视角：**为什么 LLM 输出不确定 → 需要评测而非传统断言**
