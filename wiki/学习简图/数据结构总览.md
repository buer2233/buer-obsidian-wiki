# 数据结构总览（速查图）

> **一句话定义**：一张 12 宫格思维导图，把 **12 种基础数据结构** 的「**是什么（描述）→ 什么时候用（适用）→ 怎么写（Python）**」压到一眼可查——用途是**面试前扫一遍**、以及**动手前选型的那 30 秒**。

## 一、12 种结构速查表

| # | 结构 | 一句话描述 | 适用场景 | Python 惯用写法 |
|---:|---|---|---|---|
| 1 | **数组 Array** | 连续内存，O(1) 随机访问 | 快速访问、固定大小数据存储 | `arr[i]` |
| 2 | **队列 Queue** | FIFO，先进先出 | 任务调度、广度优先搜索 | `q.append(x)` / `q.popleft()` |
| 3 | **栈 Stack** | LIFO，后进先出 | 函数调用、表达式求值、回溯 | `stack.append(x)` / `stack.pop()` |
| 4 | **链表 Linked List** | 指针连接节点 | 动态大小、频繁插入删除 | `node.next` |
| 5 | **树 Tree** | 层级关系 | 层级数据、组织结构 | 嵌套字典 / 对象实现 |
| 6 | **二叉树 Binary Tree** | 每节点最多两个孩子 | 表达式树、树形结构 | `root.left` / `root.right` |
| 7 | **二叉搜索树 BST** | 左小右大 | 快速查找、有序数据操作 | `inorder(root)`（中序遍历即有序） |
| 8 | **多叉树 N-ary Tree** | 子节点用 children 列表 | 目录结构、组织架构 | `children=[]` |
| 9 | **哈希表 Hash Table** | key → value 映射 | 快速查找、去重计数 | `d[key]=val` |
| 10 | **堆 Heap** | 完全二叉树 + 堆序（图示为小根堆） | 优先队列、Top K 问题 | `heapq.heappush(h,x)` |
| 11 | **图 Graph** | 顶点和边 | 社交网络、路径搜索 | `graph={u:[v]}` |
| 12 | **B 树 / B+ 树** | 多路平衡查找树 | 数据库索引、大量有序数据、范围查询 | `B+树: leaf → leaf` |

## 二、按「选型直觉」重组

图是按编号排的，但**实际选型是按问题特征找结构**。同一个 12 宫格换一个维度读：

| 你的问题长什么样 | 该选谁 | 理由 |
|---|---|---|
| 「我要按下标 O(1) 拿数据，长度基本不变」 | 数组 | 连续内存 + 随机访问 |
| 「我要先进先出地排队处理」 | 队列 | FIFO；BFS 的天然容器 |
| 「我要能回退到上一步」 | 栈 | LIFO；回溯 / 撤销 / 递归展开 |
| 「我要频繁在中间插入删除」 | 链表 | 改指针即可，不搬数据 |
| 「我要表达层级 / 父子关系」 | 树 / 多叉树 | 目录、组织架构、DOM |
| 「我要有序且能快速查」 | BST | 中序遍历天然有序 |
| 「我要 O(1) 查 key」 | 哈希表 | 映射查找 / 去重计数 |
| 「我每次只要最大 / 最小的那个」 | 堆 | 优先队列、Top K |
| 「我要表达任意两点的连接关系」 | 图 | 社交网络、路径搜索 |
| 「我的数据大到内存放不下、还要范围查询」 | B+ 树 | 数据库索引的标准答案 |

## 三、图里没说、但面试会追问的三组对照

图是**速查**，省略了复杂度与取舍。以下三组是这张图最容易被打穿的地方：

| 对照 | 关键差异 | 面试官想听的落点 |
|---|---|---|
| **数组 vs 链表** | 数组随机访问 O(1) 但插入删除 O(n)；链表插入删除 O(1) 但访问 O(n) | 取决于**读多写多**——读多选数组，写多选链表 |
| **哈希表 vs BST** | 哈希 O(1) 但**无序**、不支持范围查询；BST 有序 O(log n) 但需维护平衡 | 「要范围查询就别用哈希」 |
| **堆 vs 排序** | Top K 用堆是 O(n log k)，全排序再取前 k 是 O(n log n) | 数据量大、只要前 k 个时，堆是更优解 |

> [!key-insight] 这张图的正确用法
> 它不是用来"背"的，是用来**建立索引**的——记住「12 个格子里大概有什么」，真正答题时再去 [[wiki/语雀/数据结构、算法、设计模式/数据结构|数据结构]] 查细节。
> **速查图的价值在于"知道去哪找"，而不是"全都记住"。**
